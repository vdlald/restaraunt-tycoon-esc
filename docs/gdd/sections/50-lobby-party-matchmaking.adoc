== 5. Лобби, группы и матчи

=== 5.1. Place и телепортация

* Experience содержит публичный *Lobby place* и отдельный *Match place*.
* Лидер запускает матч вручную из Lobby. Сервер резервирует Match server через `TeleportService:ReserveServer` и телепортирует в него текущий состав группы.
* Каждый матч изолирован: в reserved server находится только одна группа.
* После победы, поражения или досрочного завершения активные участники возвращаются вместе в Lobby place.

=== 5.2. Группа

* Группа содержит от одного до четырёх игроков. Её может создать любой игрок в лобби.
* Приглашать может только лидер; кандидат должен быть онлайн-другом в этом experience.
* Приглашение действует до отмены либо до изменения состояния группы, из-за которого оно становится невалидным.
* Лидер может исключать участников в Lobby и во время Preparation. Исключённый участник Match немедленно возвращается в Lobby.
* Игрок может покинуть группу сам. Во время Match он освобождает слот и возвращается в Lobby; матч для остальных продолжается.
* При выходе лидера лидерство получает участник, который раньше остальных вступил в группу. Подготовка или обслуживание продолжаются, а новый лидер получает права управления фазами и досрочного завершения.
* После окончания матча группа сохраняется и может сразу начать следующий матч из Lobby.

=== 5.3. Вход в активный матч

* Во время Preparation лидер может пригласить нового игрока, если в группе есть свободный слот.
* После принятия приглашения сервер повторно проверяет группу, фазу и вместимость, затем сразу телепортирует игрока в тот же reserved Match server.
* С началом Service состав блокируется: новые приглашения, исключение и добровольное присоединение недоступны.

=== 5.4. Серверная авторизация

* Клиент отправляет только запросы действий группы; сервер проверяет лидерство, состав, фазу, лимит участников и актуальность приглашения.
* Временные данные группы, приглашений и присутствия хранятся в `MemoryStore`; межсерверные уведомления доставляются через `MessagingService`.
* Reservation access code и teleport context являются серверными данными и не передаются в UI или клиентские снимки группы.
